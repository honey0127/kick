# Safe Zone

주차한 전동 킥보드 사진으로 보행 공간을 막고 있는지 확인하는 Android 앱입니다. AI 분석 서버는 [`ai/`](ai/README.md) 폴더에 있습니다.

> **현재 상태:** 서버 주소를 설정하면 `ai/` 의 AI 서버로 실제 분석을 합니다 (아래 "AI 분석 연결 방법").
> 주소를 설정하지 않으면 사진을 보지 않는 UI 확인용 임시 결과를 쓰고, 결과 화면에 "테스트용 임시 결과"라고 표시됩니다.
>
> **주의:** 킥보드 인식 모델(`ai/models/kick_seg.pt`)은 공개 데이터셋으로 학습한 첫 버전입니다. 직접 찍은 반납 사진으로 판정 정확도를 잰 적은 아직 없습니다 ([ai/README.md](ai/README.md#0-1-킥보드-모델-roboflow-universe-공개-데이터셋으로-학습)).

## 화면 흐름

```
AI 서버 연결:  홈 ─ 사진 촬영하기 ─→ 위치 확인 (①) ─→ 촬영 ─→ 사진 확인 ─→ 분석 중 (②) ─→ 결과 ─→ 반납 완료 (③, 양호일 때)

임시 분석기:   홈 ─┬─ 사진 촬영하기 ───→ 촬영 ──┬─→ 사진 확인 ─→ 분석 중 ─→ 결과
                  └─ 갤러리에서 선택하기 → 갤러리 ┘
```

- **위치 확인(①)과 반납 완료(③)는 AI 서버 주소를 설정한 경우에만** 나옵니다. 위치 권한을 받아 현재 위치를 서버에 보내고, 주차할 수 있는 곳이면 촬영으로 넘어갑니다.
- **AI 서버에 연결한 경우에는 갤러리 버튼이 없습니다.** 위치를 확인한 그 자리에서 찍은 사진만 받기 위해서입니다 (갤러리에서는 다른 곳·다른 때 찍은 사진을 고를 수 있음).
  금지 구역·서비스 지역 밖·GPS 정확도 부족이면 서버가 보낸 안내와 "다시 확인하기"를 보여 줍니다.
- 서버 주소가 없으면(임시 분석기) 위치 확인 없이 바로 촬영/갤러리로 가고, 반납 완료 단계도 없습니다.
- 결과가 양호(SAFE)이면 "반납 완료하기"를 눌러 서버에 반납 완료(③)를 알립니다. 서버가 확인해 주면 반납 완료 화면(구역 이름, 반납 번호)으로 넘어갑니다.
  누르지 않고 나가면 반납 완료를 알리지 않습니다. 결제는 범위에서 뺐습니다.
- **반납 토큰이 만료되면**(위치 확인 후 10분 경과, 사진 판정 10회 초과, 서버 재시작) 분석 중 화면이나 결과 화면에 "위치 다시 확인하기"가 나옵니다.
  누르면 위치 확인을 다시 거쳐 촬영으로 이어집니다.

| 결과 | 메인 버튼 | 이동 |
|---|---|---|
| 주차 양호 (SAFE) | 반납 완료하기 (임시 분석기: 홈으로 돌아가기) | 반납 완료 화면 → 홈 (임시 분석기: 홈) |
| 주차 위치 확인 필요 (UNSAFE) | 다시 주차하기 (+ 홈으로) | 촬영 (또는 홈) |
| 판단 보류 (UNCERTAIN) | 다시 촬영하기 | 촬영 |

- 사진 확인 화면의 "다시 선택하기"는 사진을 가져온 곳으로 돌아갑니다 (촬영 → 촬영 화면, 갤러리 → 갤러리 다시 열기).
- 분석 중 뒤로 가면 분석이 취소되고 사진 확인 화면으로 돌아갑니다.
- 결과 화면에서 뒤로 가면 홈으로 갑니다.

## 구현된 기능

### 홈
- 로고, 안내 문구, 임시 일러스트(아이콘), "사진 촬영하기" 버튼. "갤러리에서 선택하기" 버튼은 서버 주소가 없을 때(임시 분석기)만 나옴

### 위치 확인 (`LocationCheckScreen`, 서버 연결 시)
- 화면에 들어오면 위치 권한 요청. 주차 구역을 가리려면 **정확한 위치** 권한이 필요함
  - '대략적 위치'만 허용한 경우: 위치를 묻지 않고 "정확한 위치 권한이 필요해요"와 다시 요청(또는 설정으로 이동) 버튼을 보여 줌
- 켜져 있는 위치 제공자(GPS, 네트워크, Android 12 이상은 통합 제공자)에 동시에 물어 가장 정확한 위치를 씀.
  ±15m 이내 위치가 오면 바로 쓰고, 덜 정확한 위치가 먼저 오면 5초만 더 기다림. 20초 안에 새 위치를 못 얻으면 실패로 안내하며, 기기에 남아 있던 예전 위치는 쓰지 않음
- 서버 판정에 따라 통과(다음 단계로 이동) / 거절(서버 안내 문구와 "다시 확인하기") / 실패(위치를 못 얻었거나 서버에 연결하지 못함)

### 촬영 (`PhotoSelectScreen`)
- CameraX 카메라 미리보기, 원형 촬영 버튼, 촬영 안내 3줄
- 미리보기 위에 파란 촬영 틀과 "킥보드 전체와 보도 양쪽 끝이 틀 안에 들어오게" 안내.
  가까이에서 찍어 킥보드가 잘리거나 보도 양 끝이 안 보이면 서버가 판단을 보류하므로, 찍기 전에 거리를 맞추게 함 (서버 웹 화면의 틀과 같은 비율·색)
- 화면에 들어오면 카메라 권한 요청
  - 거부: 권한 안내와 "카메라 권한 허용하기"
  - 두 번 거부해 시스템이 요청을 막은 경우: "설정에서 허용하기" → 앱 설정 화면. 설정에서 허용하고 돌아오면 바로 카메라가 켜짐
- 촬영 사진은 앱 캐시에 저장하고, 새로 찍으면 이전 사진은 지움

### 갤러리 선택 (서버 주소가 없을 때만)
- Android Photo Picker 사용 (저장소 권한 불필요, 사용자가 고른 사진 1장만 앱에 전달)

### 사진 확인 (`PhotoPreviewScreen`)
- 원본 비율을 유지해 사진 표시
- 사진을 불러오지 못하면 안내를 보여 주고 "주차 상태 분석하기" 버튼을 막음
- 화면 폭이 좁거나 글자 크기가 크면 버튼을 세로로 쌓음

### 분석 중 (`AnalyzingScreen`)
- 진행 표시와 안내 문구
- 분석 중 같은 요청이 다시 들어오면 무시 (중복 요청 방지)
- 실패하면 오류 안내와 "다시 시도하기" (같은 사진으로 재시도)
- 서버가 반납 토큰을 더 받지 않으면(만료 등) 다시 시도해도 실패하므로 "위치 확인을 다시 해 주세요"와 "위치 다시 확인하기"

### 결과 (`ResultScreen`)
- SAFE / UNSAFE / UNCERTAIN을 한 화면에서 아이콘, 색, 문구, 버튼으로 구분
- 분석 근거 카드: 분석 결과에 들어 있는 항목만 표시하고, 근거가 없으면 카드를 표시하지 않음
- 판정 근거 이미지 카드: AI 서버가 보내 준 그림(AI가 인식한 영역을 색칠한 사진, 위에서 내려다본 그림)을 색 설명과 함께 표시. 임시 결과에는 없음
- 임시 결과(Mock)는 화면 맨 위에 "테스트용 임시 결과예요. 실제 AI 분석이 아닙니다." 안내
- 서버 연결 시 양호 결과의 메인 버튼은 "반납 완료하기". 처리 중에는 버튼을 막고, 실패하면 이유를 보여 줌
  (서버에 연결하지 못함: 다시 누르기 / 반납 토큰 만료: "위치 다시 확인하기")

### 반납 완료 (`ReturnDoneScreen`, 서버 연결 시)
- 서버가 반납 완료를 확인해 준 뒤에만 표시. 서버가 돌려준 구역 이름과 반납 번호를 보여 주고, 없는 값은 표시하지 않음

### 공통
- 디자인 시스템: Primary `#31866B`, 흰 배경, 좌우 여백 24dp, 버튼 높이 56dp
- 라이트 테마 고정 (다크 모드와 배경화면 색상 연동 끔)
- 화면 회전 시 사진, 분석 진행, 결과 상태 유지
- 상태바·내비게이션바 영역 확보 (edge-to-edge)

## AI 분석 연결 방법

화면은 `PhotoAnalyzer`, `ReturnApi` 인터페이스만 사용하고, `navigation/AppNavigation.kt` 가 서버 주소에 따라 구현을 고릅니다.

| 서버 주소 | 반납 순서 |
|---|---|
| 있음 | ① `RemoteReturnApi` 가 `/api/return/location` 으로 위치 확인 → 반납 토큰 발급 → ② `RemotePhotoAnalyzer` 가 토큰과 함께 `/api/return/photo` 로 사진 판정 → ③ 양호면 `/api/return/complete` |
| 없음 (기본) | 위치 확인 없음. `MockPhotoAnalyzer` 가 약 2초 뒤 SAFE → UNSAFE → UNCERTAIN 순서로 정해진 결과 |

서버가 단계를 검사하므로 위치 확인 없이 사진만 보내면 거절되고, 한 번의 위치 확인으로 사진 판정은 10번까지 할 수 있습니다.
위치 확인 후 10분이 지나면 토큰이 만료되어 처음부터 다시 해야 합니다. 서버는 토큰을 메모리에만 두므로 서버를 다시 시작해도 같습니다.
앱은 서버가 토큰을 받지 않으면(HTTP 410/429/409) "위치 다시 확인하기"로 안내합니다.

반납 순서에서 앱은 `/api/return/photo` 만 씁니다. 토큰이 없다고 세션 없는 `/api/analyze` 로 돌려 보내지 않으므로,
서버를 `KICK_OPEN_ANALYZE=1` 로 켜 두어도 앱에서 위치 확인을 건너뛸 수 없습니다. (`/api/analyze` 는 기기 테스트처럼 분석기만 따로 쓸 때만 씁니다)

**1. AI 서버 실행** (`ai/` 폴더, 자세한 설치는 [ai/README.md](ai/README.md))

```bash
.venv/Scripts/python -m uvicorn server.main:app --host 0.0.0.0 --port 8000
```

**에뮬레이터 위치**: 서버는 `ai/server/zones.geojson` 의 구역(지금은 경북대 북문 주변 예시)으로 반납 가능 여부를 판단합니다.
에뮬레이터의 Extended Controls(⋯) → Location 에서 구역 안 좌표(예: 위도 35.89265, 경도 128.609)를 지정해야 위치 확인을 통과합니다.

**2. 앱에 서버 주소 지정** — `local.properties` 에 한 줄 추가 (PC마다 다르므로 git 에 올리지 않음)

```properties
# 에뮬레이터에서 같은 PC의 서버: 10.0.2.2 / 실제 휴대폰: PC의 와이파이 IP (예: 192.168.0.10)
analysis.server.url=http://10.0.2.2:8000
```

명령줄에서는 `./gradlew assembleDebug -PanalysisServerUrl=http://10.0.2.2:8000` 로도 지정할 수 있습니다.
디버그 빌드만 `http://` 를 허용합니다. 출시 빌드는 `https://` 서버가 필요합니다.

**판정 변환**: 서버 `APPROVE / REJECT / RETAKE` → 앱 `SAFE / UNSAFE / UNCERTAIN`.
분석 근거에는 서버가 실제로 잰 값(남은 통행폭 또는 보도 폭 점유율)과 서버가 돌려준 사유 문구만 넣습니다.
판단 보류(`RETAKE`)는 서버가 폭을 믿을 수 없다고 한 경우라, 잰 값은 빼고 사유 문구만 보여 줍니다.
서버가 보낸 근거 이미지(`overlay_jpeg`, `bev_jpeg`)는 결과 화면의 "판정 근거 이미지" 카드에 표시합니다.

**연결이 안 될 때**: 위치 확인 화면에 "위치를 확인하지 못했어요." 또는 분석 중 화면에 "분석하지 못했어요."가 나오면 Android Studio의 Logcat에서 `SafeZone`으로 검색합니다.
서버가 꺼져 있는지, 주소가 틀렸는지, 서버가 어떤 오류(404 등)를 돌려줬는지가 경고 로그로 남습니다.
앱 문제인지 연결 문제인지 가리려면 에뮬레이터 안의 Chrome 에서 `http://10.0.2.2:8000/api/health` 를 열어 봅니다.
PC 브라우저의 `http://127.0.0.1:8000/api/health` 는 열리는데 에뮬레이터에서는 안 열리면, 앱이 아니라 에뮬레이터와 PC 사이의 연결 문제입니다.

```

    ├── photo/PhotoPreviewScreen.kt  사진 확인
    ├── analysis/AnalyzingScreen.kt
    ├── analysis/AnalysisViewModel.kt  분석 요청·중복 방지·재시도·취소
    ├── result/ResultScreen.kt

```

## 실행

Android Studio에서 `File > Open`으로 이 폴더를 열고 ▶ Run 'app'을 누릅니다.

터미널에서 실행하는 경우:

```bash
./gradlew assembleDebug        # APK 빌드
./gradlew testDebugUnitTest    # 단위 테스트 (Robolectric, 기기 불필요)
```

`SDK location not found` 오류가 나면 프로젝트 폴더에 `local.properties`를 만들고 Android SDK 경로를 적습니다. 이 파일은 PC마다 다르므로 git에 올리지 않습니다.

```properties
sdk.dir=C\:\\Users\\<사용자>\\AppData\\Local\\Android\\Sdk
```

## 테스트

`./gradlew testDebugUnitTest`로 기기 없이 실행합니다.

| 파일 | 확인 내용 |
|---|---|
| `AppFlowTest` | 서버 주소가 없는 경우의 흐름: 촬영 화면 진입(틀·안내 표시), 갤러리 버튼이 사진 선택기 실행, 갤러리 선택 → 사진 확인 → 분석 → 결과 → 홈, 분석 중 뒤로 가기(취소), 결과에서 뒤로 가기 |
| `LocationFlowTest` | 서버에 연결된 경우의 흐름(가짜 위치·가짜 서버): 홈에 갤러리 버튼 없음, 위치 통과 → 촬영, 위치 거절, 양호 → 반납 완료 → 완료 화면 → 홈, 분석 중·반납 완료 때 토큰 만료 → 위치 확인으로 복귀 |
| `MainActivityTest` | 실제 MainActivity 의 홈 화면 표시 (다음 화면은 PC 의 서버 주소 설정에 따라 달라지므로 위 두 테스트에서 확인) |
| `LocationCheckScreenTest` | 위치 권한 수준별 동작: 정확한 위치 → 확인 시작, 대략적 위치·권한 없음 → 안내만 하고 위치를 묻지 않음 |
| `CameraPermissionRequiredTest` | 카메라 권한 안내 문구와 버튼 (다시 요청 / 설정으로 이동) |
| `AnalysisViewModelTest` | 분석 성공, 중복 요청 무시, 실패 후 재시도, 취소, 반납 토큰 만료 구분 |
| `ReturnViewModelTest` | 위치 확인 통과·거절·실패, 반납 완료 성공·토큰 만료·연결 실패 후 재시도, 초기화 |
| `MockPhotoAnalyzerTest` | 결과 순서, 모든 결과에 임시 결과 표시 |
| `RemotePhotoAnalyzerTest` | 서버 응답 → 앱 결과 변환(근거 이미지 포함), 가짜 HTTP 서버로 사진 업로드, 서버 오류 시 실패 처리와 원인 기록, 토큰 없이는 요청하지 않음, 410/429/409 는 토큰 만료로 구분 |
| `RemoteReturnApiTest` | 가짜 HTTP 서버로 위치 확인·반납 완료 요청과 응답 변환, 토큰 저장·삭제 |
| `PickBestLocationTest` | 여러 위치 제공자 가운데 어떤 위치를 언제 고르는지 (정확한 위치 즉시 사용, 덜 정확하면 잠깐 대기, 실내에서 GPS 무응답, 전부 무응답) |
| `ResultScreenTest` | 상태별 문구와 버튼, 결과에 든 근거만 표시, 근거 이미지 카드, 임시 결과 안내, 반납 완료 버튼의 처리 중·실패 표시 |
| `ReturnDoneScreenTest` | 반납 완료 화면이 서버가 돌려준 구역 이름·반납 번호만 표시 |

갤러리(Photo Picker)와 카메라, GPS 는 시스템 기능이라 단위 테스트에서는 결과를 직접 넣어 확인합니다.
`LocationFlowTest` 는 카메라로 촬영할 수 없어서, 테스트에서만 반납 순서의 갤러리를 켜고(`galleryInReturnFlow = true`) 사진을 넣어 줍니다.

### 기기에서 실행하는 테스트

`ServerRoundTripDeviceTest`는 에뮬레이터나 휴대폰(Android 8.0 이상)이 필요합니다. Android Studio에서 파일을 열고 클래스 이름 옆의 ▶를 누르거나 `./gradlew connectedDebugAndroidTest`로 실행합니다.

기기 안에서 가짜 서버를 띄워 사진 전송 → 응답 해석 → 근거 이미지가 화면에 그려지는 것까지 확인합니다. AI 서버와 모델 없이 실행되므로, 판정이 맞는지는 이 테스트로 알 수 없습니다.

## 아직 구현되지 않은 것

- 킥보드 인식 모델의 실사진 검증 — 공개 데이터셋으로 학습한 첫 버전(시험 mask mAP50 0.671, 국내 보도 사진 0.812, 목표 0.85)이고, 넘어진 킥보드는 학습 데이터가 없어 판정하지 못함
- 기기에서 실제 AI 서버에 연결한 반납 순서 확인 — 반납 완료 화면, 반납 토큰 만료 안내, 위치 제공자 변경을 넣은 뒤로는 에뮬레이터가 PC 의 서버에 연결되지 않아(연결 시간 초과, 원인 미확인) 확인하지 못함.
  이 부분은 가짜 서버를 쓰는 단위 테스트로만 확인했고, 에뮬레이터에서는 서버 주소 없이 실행해 촬영 틀·촬영·사진 확인·결과 화면과, 서버 주소를 넣고 실행해 위치를 얻어 서버에 요청을 보내는 데까지 확인함
- 실제 휴대폰에서의 위치 확인 — 에뮬레이터에서만 실행해 봄. 실내·실외에서 위치가 얼마나 빨리, 얼마나 정확하게 잡히는지는 재 보지 않음
- 기기 번호 입력 — 지금은 위치 확인 때 고정값(`SAFEZONE-APP`)을 보냄
- 홈 화면의 디자인된 일러스트 (현재는 아이콘으로 만든 임시 그림)
- 출시용 빌드 설정 (코드 축소 미적용, 디버그 APK 약 24MB)
