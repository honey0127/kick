# 중간 활동 보고 — AI 학습 내용 요약

## 1. 목표
공유 킥보드·전기자전거 반납 사진을 AI가 보고, 기기가 차도·점자블록·횡단보도를 막고 있거나 보도 폭을 60% 이상 차지하면 반납을 거절한다.
판정에 필요한 바닥(보도·차도·점자블록·횡단보도)을 픽셀 단위로 구분하는 **바닥 인식 모델**을 먼저 학습했다.

## 2. 왜 직접 학습했나
처음에는 공개된 사전학습 모델(Cityscapes SegFormer, 유럽 차량 시점 데이터)을 썼다.
실제 반납 사진(야간, 국내 보도)에서 보도를 **차도로 오인해 정상 주차를 거절**하는 문제가 생겼다.
해외 데이터와 국내 보행 환경이 달라서 생긴 문제(도메인 차이)라고 판단하고, 국내 보행자 시점 데이터로 다시 학습했다.

## 3. 데이터
- 출처: AI Hub「인도 보행 영상」Surface(바닥 폴리곤 라벨)
- 원본 9종 라벨 → 판정에 필요한 4개 클래스로 재분류
  - 보도: 블록, 시멘트, 아스팔트, 우레탄 보도 등
  - 차도: 차도, 이면도로, 자전거도로
  - 점자블록
  - 횡단보도
  - 맨홀, 가로수 등 '주의구역'은 제외
- 사용량: 800개 촬영 묶음에서 2프레임마다 1장씩 뽑아 **23,346장**
  - 학습 19,956장, 검증 2,360장, 시험 1,030장
- 분할은 **촬영 묶음 단위**로 했다. 같은 장소의 연속 프레임이 학습과 시험에 함께 들어가면 점수가 실제보다 높게 나오기 때문이다.

## 4. 학습 방법
| 항목 | 내용 |
|---|---|
| 모델 | YOLO11n-seg (COCO 사전학습 가중치에서 전이학습) |
| 설정 | 30 epoch, 입력 640px, batch 8, AdamW |
| 증강 | 밝기 변화 강하게(야간·역광 대비), 회전 ±5°, 좌우 반전, 모자이크 |
| 환경 | GTX 1050 Ti (4GB) — 메모리 부족으로 혼합정밀도(AMP) 끄고 batch 8 |
| 소요 | 약 11시간 (중간에 멈췄다가 저장 지점부터 이어서 학습) |

## 5. 결과 (학습에 쓰지 않은 시험 데이터 1,030장)
| 클래스 | mask mAP50 |
|---|---|
| 차도 | 0.881 |
| 점자블록 | 0.873 |
| 보도 | 0.818 |
| 횡단보도 | 0.796 |
| **전체** | **0.842** (mAP50-95 0.705) |

- 정확도는 학습 1 epoch 0.555에서 30 epoch 0.818(검증 데이터 기준)로 올랐다. 마지막 5 epoch는 거의 그대로여서 더 학습해도 크게 오르지 않을 것으로 본다.
- 속도: 사진 1장 인식 약 10ms, 판정까지 전체 약 0.2초 → 반납 화면에서 바로 쓸 수 있다.
- 횡단보도가 가장 낮은 이유는 학습 데이터가 다른 클래스의 1/10 수준이기 때문이다.

## 6. 적용 후 확인한 점
- **좋아진 점:** 기존 모델이 '차도 위 주차'로 잘못 거절했던 야간 사진을 더 이상 차도로 판단하지 않는다.
- **남은 문제 1 — 야간 사진:** 위 야간 사진의 바닥은 보도로도 인식하지 못해 '재촬영'이 나왔다. 학습 데이터가 대부분 주간 사진이라서다.
- **남은 문제 2 — cm 실측:** 점자블록 한 장(30cm)을 자로 써서 남은 통행폭을 cm로 재는 기능은 합성 영상 테스트에서 ±15cm 이내로 맞았다. 실제 사진 40장에서는 9장만 자를 찾았다. 찾은 경우의 오차는 평균 0.9cm로 작다. 실제 블록의 이음매·그림자 때문에 검출이 불안정하다.

## 7. 다음 계획
1. 직접 찍은 킥보드·전기자전거 반납 사진 수집 및 라벨링 → 기기 인식 모델 학습
   - 현재 기기 인식은 COCO의 '자전거·오토바이'로 대신하고 있어 킥보드 인식이 약하다.
2. 야간 반납 사진을 추가해 바닥 모델 재학습
3. 점자블록 '한 장' 단위 라벨을 추가해 cm 실측 성공률 높이기
4. 줄자로 실측한 통행폭과 비교해 cm 오차 검증 (목표 ±10~15cm)
